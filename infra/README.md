# Local / self-hosted infrastructure

This directory holds the config for the two stateful services the web
platform depends on: PostgreSQL and [Garage](https://garagehq.deuxfleurs.fr/)
(S3-compatible object storage for the PDFs). Both are wired up in
`../docker-compose.yml`.

## Quick start

```sh
./infra/generate-secrets.sh   # writes infra/garage.toml (gitignored) with fresh random secrets
docker compose up -d
```

This starts:
- `postgres` — the database (`kindle` / `kindle` / `kindle`, see compose file).
- `garage` — the object storage node.
- `garage-init` — a one-shot container that bootstraps Garage (storage
  layout, bucket, access key) and exits. It's idempotent: safe to re-run
  (`docker compose up garage-init`) if it fails partway through.

Once `garage-init` finishes, fetch the generated credentials:

```sh
docker compose run --rm garage-init cat /shared/credentials.env
# or, since it already ran once:
docker compose exec garage cat /var/lib/garage/... # not applicable — read the logs instead:
docker compose logs garage-init
```

Copy the `GARAGE_ACCESS_KEY_ID` / `GARAGE_SECRET_ACCESS_KEY` lines into
`web/.env` (see `web/.env.example` for the full set of variables).

Then, from `web/`:

```sh
npm install
npx prisma migrate deploy
npm run dev
```

## Manual Garage bootstrap (fallback)

If `garage-bootstrap.sh` doesn't work against your Garage version (CLI output
format can change between releases), do it by hand:

```sh
docker compose exec garage /garage -c /etc/garage.toml status
# note the node ID printed there, or run:
docker compose exec garage /garage -c /etc/garage.toml node id -q

docker compose exec garage /garage -c /etc/garage.toml layout assign -z dc1 -c 5G <node_id>
docker compose exec garage /garage -c /etc/garage.toml layout apply --version 1

docker compose exec garage /garage -c /etc/garage.toml bucket create kindle-pdfs
docker compose exec garage /garage -c /etc/garage.toml key create kindle-app-key
docker compose exec garage /garage -c /etc/garage.toml bucket allow \
  --read --write --owner kindle-pdfs --key kindle-app-key
```

The `key create` output prints the Key ID and Secret Key once — copy them
into `web/.env` as `GARAGE_ACCESS_KEY_ID` / `GARAGE_SECRET_ACCESS_KEY`.

## Production notes

- `infra/garage.toml` (generated by `generate-secrets.sh`, gitignored — only
  `garage.toml.example` is committed) holds `rpc_secret`, `admin_token`, and
  `metrics_token`. Treat it like any other secrets file: don't commit it,
  back it up separately, and regenerate it (delete + re-run the script) if
  it ever leaks.
- `replication_factor = 1` means zero redundancy — fine for a single personal
  server, not fine if you care about not losing your books. Garage supports
  multi-node replication; see the [Garage docs](https://garagehq.deuxfleurs.fr/documentation/)
  if you want that.
- Put the web app behind HTTPS (e.g. a reverse proxy with Let's Encrypt)
  before exposing it beyond your LAN — the Android app sends the login
  password and bearer token over whatever scheme you configure.
